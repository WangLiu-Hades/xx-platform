# 总体系统架构设计

2026-10-10责任补充：下表“主责”是模块交付协调责任。公开REST端点统一由DEV-01实现和集成；DEV-03交付接入、查询、指标及数据计算模块，DEV-02负责全部页面，DEV-04负责质量/部署。通知投递与设备命令等副作用执行函数归DEV-01，不因部署在Worker进程而转归DEV-03。完整交接见[工程师任务修订版](<../project-governance/ENGINEERING_ASSIGNMENTS.md>)。本页工程目录树是目标结构，不能据此认定这些正式工程目录已经存在。

## 结论与约束

首版采用**模块化单体 API + 独立 Python 数据与分析 Worker**。Vue Web 前端调用一个 Spring Boot API；API 内按领域包隔离 M01–M14 的在线能力；Worker 负责批次标准化、伴随/碰撞/区域统计、集合运算、报表与大导出。两进程经 PostgreSQL 中的任务表和业务数据交接，以固定契约通信，不通过内部 HTTP 链式调用。源资料中的 M01–M15 是工作边界，不是 15 个微服务。系统上下文、容器、组件、依赖和数据流见 `diagrams/`。

选择理由：四类角色与强共享数据/权限/上下文契约适合单 API，长任务需要单独进程隔离 CPU/内存和失败影响。多数据库、MQ、网关和配置中心目前缺乏由源资料证明的必要规模。正式采用范围仍受 A-001/A-002/A-004/A-006 约束。

## 在线与后台边界

普通分页 CRUD、受限窗口内索引检索、bbox 点聚合、权限检查同步完成。导出、大范围检索、搜图、伴随/碰撞/区域统计、大集合运算、模型重算、批量参数下发、通知执行与报表异步完成。通知计划本身同步201创建，保存ONCE/DAILY计划及版本；调度器按唯一执行键创建async_task。其他异步创建由API在同一事务提交业务意图和 `async_task`，立即回 `202 + taskId`；Worker 使用数据库租约领取任务，心跳续租，更新进度、参数快照、结果引用和错误码。客户端轮询任务端点；WebSocket 可在已证实轮询压力后增加，首版不把 WebSocket 作为正确性前提。

统一状态：`PENDING → QUEUED → RUNNING → SUCCESS|FAILED|CANCELLED`。`RUNNING` 任务取消是请求态，Worker 在安全检查点确认后才进入 `CANCELLED`；已发送的短信/设备命令不能通过取消撤回，需显示实际送达/执行结果。`FAILED` 重试创建新尝试并保留历史尝试，任务 ID 不变。任务分类、幂等键、租约、重试和结果清理见 `08_可靠性与可观测性设计.md`。

## 跨模块上下文

`AnalysisContext` 存在服务端 `analysis_context` 表，包含创建人、权限快照版本、目标引用、数据类型、时间范围、GeoJSON 空间范围、筛选条件、来源模块、过期时间和创建时间。浏览器只持有不含敏感数据的 `contextId`，用 `POST /contexts` 创建、`GET /contexts/{id}` 恢复；跨页跳转只传此 ID。每次读取或衍生任务都**重新**执行当前用户、数据范围和目标权限校验，不能仅信任保存时的权限快照。上下文过期/源记录删除时明确提示重建；日志不记录完整敏感参数。

## 关键数据流

1. 设备/文件 → M03 接入适配 → 原始批次引用、校验隔离、去重 → 标准采集记录；入库及去重指标分开统计。
2. M05 检索 → M06 上下文 → M07 地图或 M08/M09/M10 任务；同一 `targetId + dataType + 时间范围` 契约贯通。
3. 新采集记录 → M10 规则匹配 → 告警去重 → 通知投递；发送状态与告警事件分开保存。
4. M03/M12 数据 → 指标汇总任务 → M04/M13 首页；首页不扫描全量采集明细。

## 实施次序与工程结构

M15 从首个接口起执行。第一关口是 M01/M02/M03 的契约、基础环境和 Mock；随后 M04/M05/M07/M11/M12/M13/M14 并行；M06/M08/M09/M10 接入检索、数据和任务底座；最后跨模块回归与发布演练。该顺序不是 S5 的 14 周承诺。

```text
frontend/src/{app,shared,features/{dashboard,search,map,analysis,dataset,watch,profile,operation,system}}
backend/src/main/java/.../{platform,identity,capture,context,map,analysis,dataset,watch,profile,operation,audit}
worker/{common,ingest,analysis,export,notification,report,device}
database/{migrations,seed}
docs/system-design/{api,database,diagrams,ui,adr}
deploy/{compose,config,runbooks}
tests/{contract,integration,e2e,performance,security,recovery}
```

包依赖只允许 `feature → platform interfaces` 和 `feature → its data repository`；跨业务域经公开 service interface 或任务命令，不允许双向包引用。设计审查发现的跨域主责歧义见 ISSUE-002/ISSUE-004。

## DB-DESIGN-2执行与发布边界

PostgreSQL14+使用匹配的PostGIS构建（PG14从PostGIS3.1.4起支持）。数据结构见03与database目录。PENDING完成输入准备后转QUEUED，Worker短事务SKIP LOCKED领取并增加lease_generation；完成/取消/心跳都校验当前租约。结果逐attempt写入，事务成功后更新领域published_attempt_no。Context只是过滤/目标入口，任务重放输入用固定数据集版本、明确ID或受控manifest；不复制全部采集到每个Context。

指标按批次/水位增量汇总，源采集计数单独接入；每条采集不同时写多份统计、事件和权限副本。M13复用统一指标/地图/报告。数据集版本用成员有效区间，通知计划与每次执行分开，报告预览读取历史冻结行。
