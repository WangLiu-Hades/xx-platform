# 开发联调与集成方案

## 2026-10-10实现责任澄清

以[工程师任务修订版](<../project-governance/ENGINEERING_ASSIGNMENTS.md>)及H01–H10交接为当前执行入口。原M01–M15主责表示模块交付协调；全部公开HTTP API、授权/事务/任务底座及迁移发布归DEV-01，数据接入/查询投影/指标/算法执行归DEV-03，全部前端页面归DEV-02，测试环境/部署与验收证据归DEV-04。DEV-03提交可执行SQL/查询或Worker模块给DEV-01集成，不另建公开认证后端。通知/设备控制副作用Worker由DEV-01实现，不能按进程语言统一推给数据工程师。

## 质量门禁和审查

每次合并跑静态检查、单测、OpenAPI 语法/契约、SQL migration 空库与升级库、关键 API 集成测试；每日 E2E 走登录→检索→地图→研判→布控→通知，以及设备→运维→报表。UAT 前补安全、容量和恢复演练。测试数据必须合成或经批准脱敏，不能把真实人像/IMSI放入仓库。每个版本有镜像摘要、迁移版本、回滚条件和环境差异清单。

角色 Review：DEV-01 检查 API/事务/任务/权限；DEV-02 检查页面树、GIS 和契约覆盖；DEV-03 检查数据/指标/算法版本；DEV-04 检查测试、部署、监控与恢复。发现以下任一问题退回设计：循环包依赖、模块等于服务、重复权限/任务系统、前端唯一安全校验、同步长任务、一次返回海量记录/点位、首页扫描全量、字段口径分叉、无法 Mock/本地启动/早期联调。

## 关键路径

在 ISSUE-001/011 排期裁决前不承诺周数。工程启动应先完成源基线与权限/数据契约签认；接着交付可运行的 M01/M02/M03 和 Mock；并行推进查询、地图、运维、档案；统一任务底座稳定后接入研判、数据集和布控；每阶段由 DEV-04 做契约与恢复测试，而不是到最后才做集成。

## 数据结构门禁（DB-DESIGN-2）

DEV-01/03按database/schema.sql实现领域仓库和DTO投影；DEV-02按当前193操作和api-storage-map字段来源开发；DEV-04核对数据字典、ER、SQL字段/可空性/外键、源需求578行及核心DTO映射。变更字段必须同步四份物理文档并跑真实PostgreSQL/PostGIS，而不只解析YAML或SQL。

当前隔离验证已通过63项正反例、11条查询PREPARE及2万条合成事实计划检查。追加验收包含四源payload、稳定源回放、选区覆盖公式、历史数据集成员、档案谱系、周期执行唯一、收件人通道一致、分组移场所、DESIRED/REPORTED、逐台回执和报表历史名称。生产API实现、真实算法、完整角色矩阵、升级库迁移、压测与故障恢复尚须后续工程验证；本次结果详见design-validation.md。
