## 2. 交付概览

- 新增 1 个菜单页、6 个对话组件、1 个 Pinia store、2 个工具、1 个模型客户端、1 个模型桩、2 套测试。

## 3. 交互流程（以"布控"为例）

```
用户输入：布控
  │
  ├─ 1. 本地规则引擎（utils/agentNlu.ts）
  │     归一化 → 关键词打分 → 命中「布控预警」
  │     提取条件（目标/时间/场所，本句为空）
  │     生成动作：查看布控任务 / 新建布控 / 查看布控预警结果
  │
  ├─ 2. 本地大模型（api/llm.ts，可选）
  │     系统提示词 = 角色约束 + 已识别能力 + 条件 + 聚合概况（2 个布控任务、运行中 1 个、3 条告警）
  │     POST {baseUrl}/chat/completions, stream=true → SSE 增量
  │     模型不可用/超时/空输出 → 立即使用规则应答
  │
  ├─ 3. 界面（AgentPage + AgentMessageItem + AgentActionCard）
  │     用户气泡 → 智能体气泡（思考过程、Markdown、来源标签）
  │     三张操作卡片：列/新/警 图标，新建为主操作（蓝色高亮）
  │
  └─ 4. 用户点击（stores/agent.ts → runAction）
        查看布控任务     → platform.navigate('综合布控')
        新建布控         → navigate('综合布控') + platform.formWatch() 打开新增表单
        查看布控预警结果 → platform.navigate('告警结果')
        执行前 p.allowed(page) 校验；无权限则在对话中说明，不跳转
        执行后追加一条确认消息，避免用户误以为已在对话中提交
```

其他示例：

| 输入 | 识别 | 动作 |
| --- | --- | --- |
| 新建布控 | 布控预警（mode=create） | 新建布控排第一，其余两个入口保留 |
| 查看布控预警结果 | 布控预警（mode=alerts） | 预警结果排第一 |
| 检索 460000000000001 最近24小时 | 数据检索（type=电围，target，时间） | 四类检索入口，电围排第一；目标与时间带入查询表单 |
| 新建伴随分析 | 数据研判（subtype=伴随） | 新建伴随分析排第一，另附查看/新建碰撞、区域统计 |
| 设备在线率 | 运维服务 | 运维首页、设备管理、参数配置、设备分布 |
| 运维报表 | 运维报表 | 查看运维报表、新建运维报表 |

## 7. 关键设计决策

### D1 规则引擎在前，模型在后

大模型只负责"把已经确定的能力和条件说清楚"，不负责决定页面。原因：模型可能虚构页面、按钮或"已执行"结果；业务入口必须可枚举、可测试、可审计。收益是**模型离线也能完成全部跳转**，模型在线只提升表达自然度。

### D2 动作卡片由本地目录生成

`AgentAction` 固定包含 `kind/page/handler/filters`，`page` 必须存在于 `domain.ts`。新增能力只改一个目录文件；按钮顺序可按 `mode`（查看/新建/预警）调整。模型无法注入新按钮。

### D3 只发送聚合概况

系统提示词包含：能力目录、识别到的用户条件、记录/任务/告警/设备等**数量**。不包含采集明细、人员姓名、身份证、手机号。HTTP 模式下不写死数量，提示模型"以服务端为准"。

### D4 严格降级

- 未启用模型：`status=disabled`，直接规则应答，不发请求。
- 未连接/超时/空输出：规则应答，并在气泡下说明"本地模型未连接/调用失败"。
- 已输出部分后失败或用户停止：保留已生成片段，标记"已停止"。
- 任何路径都不阻塞三个动作卡片的显示与点击。

### D5 复用原业务页面与表单

"新建布控"调用 `platform.formWatch()`，与按钮/右键菜单走同一个表单和校验；"去检索"复用 `navigate(page, filters)`。没有为智能体重写一套提交逻辑，避免两份业务规则。

### D6 权限前置校验

`runAction` 在跳转前调用 `platform.allowed(page)`；无权限时在对话中说明原因并记录，不静默失败。页面隐藏按钮仍不是授权机制，真实后端仍需逐请求校验。

### D7 Mock 相对时间基准

演示数据日期固定（2026-10），若"最近24小时"以当前系统时间为基准会查不到记录。Mock 模式下相对时间以**演示数据最新采集时间**为基准，HTTP 模式用真实当前时间。这样演示既有时间条件又能看到结果，且不伪造服务端时间。

### D8 本机会话，不写数据库

会话与模型配置存 localStorage（`vue-agent-conversations-v1`、`vue-agent-llm-config-v1`），最多 30 个会话/每会话 120 条消息。原因：当前契约没有对话接口，不能假装已服务端持久化。文档中明确列为待确认项。

### D9 受限 Markdown

模型输出先整体 HTML 转义，再只开放加粗、行内代码、列表、小标题；不使用 `v-html` 直接渲染原始文本。`agentMarkdown` 有转义单元测试。

## 8. 开发中发现并修正的问题

| 问题 | 现象 | 处理 |
| --- | --- | --- |
| 流式内容不刷新 | 模型已生成完整回答，气泡仍停在"正在处理"、正文为空 | 助手消息入数组后改用数组中的响应式代理（`conversation.messages.at(-1)`）更新；直接改原始对象不会触发子组件重渲染 |
| 类名冲突 | 对话页头部 `.identity` 与顶栏身份选择器同名，被全局 `width:210px` 影响，且 e2e 选择器命中两个元素 | 改为 `.agent-identity`，并让名称区可伸缩省略 |
| 快捷词重复 | 有动作卡片时底部再出现同名建议，信息重复 | 有动作卡片时隐藏建议 chips；无动作时才展示 |
| 相对时间查不到演示数据 | "最近24小时"按当前时间过滤，Mock 记录是 10 月固定日期 | 见 D7 |
| 测试脚本探活噪音 | 未启动模型时浏览器记录 `ERR_CONNECTION_REFUSED`，导致冒烟/回归把控制台错误计为失败 | 回归脚本通过 `addInitScript` 关闭本地模型；智能体专项单独用模型桩运行 |

## 10. 已知限制与待确认

1. **后端编排缺失**：当前意图识别在前端；若后端要统一提示词、会话、审计，需要新增契约接口，前端改为调用后端。
2. **会话不跨设备**：会话仅存本机浏览器；换浏览器/清缓存会丢失；没有服务端留存与合规审计。
3. **模型效果未验收**：仅验证链路与兜底；回答质量、首 token 延迟、并发、显存占用需在目标机器测。
4. **动作参数有限**：当前支持目标、时间、场所、类型和"新建"意图；不支持"把告警通知改成邮件并每天10点发送"这类多步参数配置，需到表单中完成。
5. **HTTP 菜单依赖**：真实后端 `/me` 菜单需包含"智能对话"，否则登录回落到系统首页；契约桩已补，真实后端待同步。
6. **对话内容不脱敏**：用户输入什么就发给本地模型什么；如涉及敏感查询，需在部署评审中约定提示词脱敏或禁用模型。
7. **未做语音输入/图片理解**：输入区是文本，不含多模态。

## 11. 回滚方式

需要回到改造前状态时，按以下顺序（不涉及数据迁移）：

1. `src/domain.ts` 移除"智能助手"分组和 `homePage`，恢复 28 菜单；
2. `src/App.vue`、`src/stores/platform.ts` 恢复默认"系统首页"，移除 `AgentPage` 注册、悬浮按钮与 `chat` 类；
3. 删除 `src/pages/AgentPage.vue`、`src/stores/agent.ts`、`src/api/llm.ts`、`src/utils/agentNlu.ts`、`src/utils/agentMarkdown.ts`、`src/components/agent/`、`scripts/llm-stub.mjs`、`tests/agent.test.ts`、`tests/vue-agent.e2e.cjs`；
4. `src/mock/fixture.json` 移除角色中的"智能助手"；`repository.ts` 的迁移可保留（对旧数据无副作用）或一并移除；
5. 恢复被本轮修改的测试脚本与文档；
6. 浏览器 localStorage 中的 `vue-agent-conversations-v1`、`vue-agent-llm-config-v1` 与 Mock 数据 `vue-prototype-mock-v2` 可手动清除。

建议回滚前先复制 `apps/web/src` 与 `apps/web/tests` 当前目录。
