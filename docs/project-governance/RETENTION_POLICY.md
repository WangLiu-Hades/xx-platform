# 统一保存策略：一年

版本：PD-2026-10-19.v1；决定：RETENTION-2026-10-19。2026-10-19用户明确将统一保存期限由一个月调整为一年，用于解决F08。机器入口为[provisional-policy.json](provisional-policy.json)。本次确认只覆盖保存期限，其他待确认事项及真实服务实现状态分别保留。

## 期限、起算与范围

默认物理保存期限为一年，即12个自然月，按Asia/Shanghai从起算时刻计算，到期时刻以UTC存储；目标月份没有同一日时取该月最后一日，例如2024-02-29至2025-02-28，不固定换算365天。

| 类别 | 起算时刻 | 默认期限 |
| --- | --- | --- |
| 采集事实、原图及受控附件 | 采集capturedAt；文件按自身ACTIVE时间 | 12个自然月 |
| 任务、参数快照、结果、导出和报表 | 任务终态；文件/冻结报表发布ACTIVE时间 | 12个自然月 |
| Context及审批申请/决定等元数据 | 对象创建时刻；其关联审计按occurredAt | 12个自然月 |
| 操作/安全审计、短信/告警等业务记录 | 对应occurredAt/创建时刻 | 12个自然月 |
| 数据库及受控文件备份 | 备份完成时刻 | 12个自然月，完整恢复链继续保护 |

会话、审批许可、游标、Context访问TTL和下载许可继续按各自时限过期，物理保存一年不授予持续访问权限。解密仍即时受控查看，不产生可长期保存的明文文件。

## 年度报表与滚动保存

滚动12个月可以覆盖一个年度长度，但年中重建上一自然年报告时，早期明细可能已到期。因此年度指标及报表须按Asia/Shanghai自然年，在相关源数据清理前完成冻结，或在同一受控流程中建立覆盖所需输入的引用保护；生成失败则延迟所需数据清理并告警，禁止先删后补零。

冻结报表、公式/算法版本、水位、授权范围、输入摘要及实际coverage从发布时刻另保存12个自然月，预览和下载同一冻结结果。源明细到期后可读取已保留的完整年报，不承诺还能任意重算已过期原始明细。部署前未采集的历史、既已删除的数据及缺来源区间继续披露实际覆盖，不能因修改期限声称历史已恢复。

清理每日02:30（Asia/Shanghai）执行的设计不变；活跃任务/报表/文件引用和备份恢复链未释放时延迟物理清理并告警，不以CASCADE破坏历史引用。过期访问仍复核授权，不能仅凭引用保护绕过访问TTL。

## 访问、算法与容量

普通明细单次查询窗口仍31天；SQL超时5秒；Context访问30分钟、游标15分钟、下载许可5分钟。RESIDENCE统计窗口仍一个自然月，标签访问7天；保存期限不是算法窗口。备份仍每周全量、WAL持续归档、文件15分钟增量。

一年数据及备份容量需按实际增长、图片体积、索引、恢复链和受保护引用重新测算；既有500GB仅是原验收下限，不代表已证明足够一年。此仓库尚无正式清理、备份和年度调度服务，本轮更新的是明确设计和机器配置，不声称已修改生产数据库或已恢复历史数据。
